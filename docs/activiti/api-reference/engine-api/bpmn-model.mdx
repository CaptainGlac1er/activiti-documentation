## Overview

The **activiti-bpmn-model** module provides a Java object model for BPMN 2.0 diagrams. It represents the in-memory structure of BPMN processes, enabling programmatic manipulation, validation, and conversion of workflow definitions.

### Key Features

- **BPMN 2.0 Compliance**: Full support for BPMN 2.0 specification
- **Type-Safe Model**: Strongly-typed Java classes for all BPMN elements
- **Extensibility**: Support for custom properties and extensions
- **Validation**: Built-in model validation
- **Serialization**: XML and JSON support

## Key Classes and Their Responsibilities

### BpmnModel

**Purpose:** Root container for the entire BPMN diagram. Represents a complete BPMN 2.0 definitions file.

**Responsibilities:**
- Holding all processes in the diagram
- Managing global elements (signals, messages, errors, item definitions)
- Providing element lookup by ID
- Storing namespace and metadata
- Tracking all flow elements
- Holding definitions-level extension attributes (`definitionsAttributes`)

**Key Properties:**
- `processes` - List of Process objects
- `signals` - Global signal definitions
- `errorMap` - Global error definitions (keyed by error ref)
- `messageMap` / `messageFlowMap` - Global messages and message flows
- `itemDefinitionMap` - Item definitions
- `dataStoreMap` - Data stores
- `pools` - Pools (collaborations)
- `namespaceMap` - Mapping of namespace prefixes to URIs
- `locationMap` / `labelLocationMap` / `flowLocationMap` - BPMN DI graphical information

**Key Methods:**
- `addProcess(Process)` - Add a process to model
- `getProcessById(String)` - Get process by ID
- `getFlowElement(String)` - Look up a flow element by ID (searches all processes and nested sub-processes)
- `getProcesses()` - Get all processes
- `getMainProcess()` - Get the main process

**When to Use:** This is your entry point to the BPMN model. All parsing and manipulation starts here.

**Design Pattern:** Composite pattern - contains and manages child elements

**Thread Safety:** Not thread-safe for modifications. Read operations are safe.

### Process

**Purpose:** Represents a single BPMN process definition within the model.

**Responsibilities:**
- Containing all flow elements of a process
- Managing process metadata (ID, name, documentation)
- Tracking data inputs and outputs
- Managing lanes
- Storing process data objects
- Handling sub-processes

**Key Properties:**
- `id` - Process identifier (inherited from `BaseElement`)
- `name` - Process name
- `executable` - Whether process can be executed (default `true`)
- `documentation` - Process documentation
- `ioSpecification` - Input/output specification
- `lanes` - Lanes of the process
- `flowElementList` - All flow elements in the process
- `candidateStarterUsers` / `candidateStarterGroups` - Candidate starter lists
- `dataObjects` - Process data objects

**Key Methods:**
- `addFlowElement(FlowElement)` - Add element to process (sets its parent container and registers it in the flow element map)
- `getFlowElements()` - Get all flow elements
- `isExecutable()` / `setExecutable(boolean)` - Check/set if executable
- `getLanes()` - Get lanes
- `getDocumentation()` / `setDocumentation(String)` - Process documentation

**When to Use:** When working with a specific process within a BPMN diagram.

**Design Pattern:** Container pattern - holds process elements

**Important:** A BpmnModel can contain multiple Process instances

### BaseElement

**Purpose:** Abstract base class for all BPMN elements. Provides common functionality.

**Responsibilities:**
- Storing the element ID
- Tracking the element's position in the source XML (`xmlRowNumber` / `xmlColumnNumber`)
- Holding custom extension elements
- Holding extension attributes (custom attributes, including `activiti:` ones)
- Supporting element identification

**Key Properties:**
- `id` - Unique element identifier
- `xmlRowNumber` / `xmlColumnNumber` - Element position in the source XML file
- `extensionElements` - Custom extension elements, keyed by name (`Map<String, List<ExtensionElement>>`)
- `attributes` - Extension attributes, keyed by name (`Map<String, List<ExtensionAttribute>>`)

**Key Methods:**
- `getId()` / `setId()` - Element identification
- `getXmlRowNumber()` / `getXmlColumnNumber()` - Source XML position
- `getExtensionElements()` / `addExtensionElement(ExtensionElement)` - Read/add custom extension elements
- `getAttributes()` / `addAttribute(ExtensionAttribute)` - Read/add extension attributes
- `getAttributeValue(String, String)` - Look up an attribute value by namespace and name

**When to Use:** As base class for all BPMN elements. Provides common functionality.

**Design Pattern:** Base Class pattern - common functionality for all elements

**Inheritance:** All BPMN elements extend this class, directly or via `FlowElement` — except the root `BpmnModel` container and the auxiliary types `GraphicInfo` and `Error`

---

### FlowElement

**Purpose:** Abstract base for elements that participate in process flow.

**Responsibilities:**
- Extending `BaseElement` with name and documentation
- Carrying execution listeners
- Referencing the parent container

**Key Properties:**
- `id` - Element identifier (inherited from `BaseElement`)
- `name` - Element name
- `documentation` - Element documentation
- `executionListeners` - Execution listeners

**Key Methods:**
- `getDocumentation()` / `setDocumentation(String)` - Element documentation
- `getExecutionListeners()` - Get execution listeners
- `getSubProcess()` - The enclosing sub-process, if any

> **Note:** The incoming/outgoing sequence flow lists (`incomingFlows` / `outgoingFlows`) are not on `FlowElement` — they are on `FlowNode`, which extends it.

**When to Use:** As base class for activities, gateways, and events.

**Design Pattern:** Base Class for the flow element hierarchy

**Subclasses:** Activity, Gateway, Event, SequenceFlow

---

### Activity

**Purpose:** Abstract base for all BPMN activities (tasks, sub-processes).

**Responsibilities:**
- Defining activity behavior
- Managing activity properties
- Handling loop characteristics
- Managing I/O specifications
- Handling boundary event attachments

**Key Properties:**
- `defaultFlow` - ID of the default outgoing sequence flow
- `forCompensation` - Whether the activity is a compensation activity
- `loopCharacteristics` - Multi-instance loop characteristics (if any)
- `ioSpecification` - Input/output specification
- `dataInputAssociations` / `dataOutputAssociations` - Data associations
- `boundaryEvents` - Boundary events attached to the activity
- `failedJobRetryTimeCycleValue` - Retry time cycle for failed jobs
- `mapExceptions` - Mapped exception entries

**Key Methods:**
- `getLoopCharacteristics()` - Get the multi-instance loop characteristics
- `hasMultiInstanceLoopCharacteristics()` - Check if the activity is multi-instance
- `isForCompensation()` - Check if it is a compensation activity
- `getIoSpecification()` - Get the I/O specification
- `getBoundaryEvents()` - Get attached boundary events

> **Note:** Loop properties (`loopCardinality`, `completionCondition`, `elementVariable`, …) are not on `Activity` — they live on `MultiInstanceLoopCharacteristics`, reached via `getLoopCharacteristics()`.

**When to Use:** As base class for all task types and sub-processes.

**Design Pattern:** Base Class for the activity hierarchy

**Subclasses:** Task, CallActivity, SubProcess, Transaction

---

### Task

**Purpose:** Base class for atomic work activities.

**Responsibilities:**
- Representing single unit of work
- Serving as the base for concrete task types

**Key Properties:**
- (none of its own - `id` from `BaseElement`, `name` from `FlowElement` via the `Activity` → `FlowNode` → `FlowElement` chain)

**Key Methods:**
- `clone()` / `setValues(Task)` - Copy support (the only members besides the inherited ones)

> **Note:** `Task` is an empty base class. Implementation details (e.g. `implementation` on `ServiceTask`) live on the concrete task types.

**When to Use:** As base for specific task types.

**Design Pattern:** Base Class for task hierarchy

**Subclasses:** UserTask, ServiceTask, ReceiveTask, SendTask, ManualTask, ScriptTask, BusinessRuleTask

---

### UserTask

**Purpose:** Represents a task performed by a human user.

**Responsibilities:**
- Defining human interaction points
- Managing assignee information
- Handling form configuration
- Supporting candidate users/groups
- Managing task properties
- Enabling form property definition

**Key Properties:**
- `assignee` - Task assignee expression
- `candidateUsers` - Candidate users (`List<String>`)
- `candidateGroups` - Candidate groups (`List<String>`)
- `formKey` - Form identifier
- `formProperties` - Form property definitions (`List<FormProperty>`)

**Key Methods:**
- `getAssignee()` / `setAssignee(String)` - Assignee expression
- `getCandidateUsers()` / `getCandidateGroups()` - Candidate users/groups
- `getFormProperties()` - Get all form properties
- `setFormKey(String)` - Set form key

**When to Use:** For any task that requires human interaction.

**Design Pattern:** Specialized Task type

**Important:** Most common task type in business processes

---

### ServiceTask

**Purpose:** Represents automated service invocation.

**Responsibilities:**
- Defining service operations
- Managing implementation details
- Managing operation references
- Enabling service integration

**Key Properties:**
- `implementation` - Implementation type (class, delegate, webService)
- `implementationType` - Implementation type
- `operationRef` - Operation to invoke
- `resultVariableName` - Variable to store the service result
- `type` - Service task type
- `customProperties` - Custom properties (`List<CustomProperty>`)
- `skipExpression` - Expression to skip the task

**Key Methods:**
- `getImplementation()` / `setImplementation(String)` - Implementation type
- `getOperationRef()` / `setOperationRef(String)` - Operation to invoke
- `getResultVariableName()` / `setResultVariableName(String)` - Result variable
- `hasBoundaryErrorEvents()` - Check for boundary error events

> **Note:** Asynchronous execution is not a `ServiceTask` property — the `asynchronous` flag is defined on `FlowNode` (see the note below the `ServiceTask` code block).

**When to Use:** For automated tasks that call external services or execute code.

**Design Pattern:** Specialized Task for automation

**Implementation Types:** class, delegateExpression, webService, operation

---

### Gateway

**Purpose:** Abstract base for decision points in process flow.

**Responsibilities:**
- Managing flow decisions
- Handling gateway types
- Supporting default flows
- Managing gateway properties
- Enabling flow control
- Tracking gateway state

**Key Properties:**
- `defaultFlow` - ID of the default outgoing sequence flow (only member of its own; `id` / `name` are inherited)

**Key Methods:**
- `getDefaultFlow()` - Get default flow
- `setDefaultFlow(String)` - Set default flow

**When to Use:** As base class for all gateway types.

**Design Pattern:** Base Class for gateway hierarchy

**Subclasses:** ExclusiveGateway, ParallelGateway, InclusiveGateway, EventGateway, ComplexGateway

---

### ExclusiveGateway

**Purpose:** XOR gateway - chooses exactly one path based on conditions.

**Responsibilities:**
- Evaluating sequence flow conditions
- Selecting single outgoing path
- Managing default flow
- Supporting conditional logic
- Handling gateway decisions
- Enabling exclusive routing

**Key Properties:**
- `defaultFlow` - Flow when no condition matches (inherited from `Gateway`; declares no members of its own)

**Key Methods:**
- `getDefaultFlow()` - Get default flow ID (inherited from `Gateway`)
- `setDefaultFlow(String)` - Set default flow (inherited from `Gateway`)

**When to Use:** For decision points where only one path should be taken.

**Design Pattern:** Specialized Gateway for exclusive choices

**Important:** Most common gateway type for business decisions

---

### ParallelGateway

**Purpose:** AND gateway - splits or joins parallel paths.

**Responsibilities:**
- Creating parallel execution paths
- Synchronizing parallel flows
- Managing fork/join behavior
- Supporting concurrent execution
- Handling parallel state
- Enabling parallel processing

**Key Properties:**
- (none of its own - inherits `defaultFlow` from `Gateway`)

**Key Methods:**
- (none of its own - inherits `getDefaultFlow()` / `setDefaultFlow(String)` from `Gateway`)

**When to Use:** For parallel execution or synchronization points.

**Design Pattern:** Specialized Gateway for parallelism

**Behavior:** All outgoing paths taken (split), all incoming required (join)

---

### Event

**Purpose:** Abstract base for all BPMN events.

**Responsibilities:**
- Defining event characteristics
- Managing event definitions
- Handling event properties
- Supporting event types
- Tracking event state
- Enabling event processing

**Key Properties:**
- `eventDefinitions` - List of event definitions
- `id` - Event identifier (inherited)
- `name` - Event name (inherited)

**Key Methods:**
- `addEventDefinition(EventDefinition)` - Add definition
- `getEventDefinitions()` - Get all definitions
- `isLinkEvent()` - Check if the single event definition is a link event
- `getErrorEventDefinition()` - Get the error definition, if any

**When to Use:** As base class for all event types.

**Design Pattern:** Base Class for event hierarchy

**Subclasses:** StartEvent, EndEvent, IntermediateCatchEvent, ThrowEvent, BoundaryEvent

---

### StartEvent

**Purpose:** Marks the beginning of a process instance.

**Responsibilities:**
- Initiating process execution
- Managing start conditions
- Handling event definitions
- Supporting interrupting behavior
- Tracking start metadata
- Enabling process initiation

**Key Properties:**
- `eventDefinitions` - Trigger conditions (inherited from `Event`)
- `initiator` - Initiator expression
- `formKey` - Form identifier
- `formProperties` - Form property definitions (`List<FormProperty>`)
- `isInterrupting` - Whether it interrupts (default `false`)
- `id` - Event identifier (inherited)
- `name` - Event name (inherited)

**Key Methods:**
- `addEventDefinition(EventDefinition)` - Add trigger (inherited from `Event`)
- `isInterrupting()` - Check interrupt mode
- `setInterrupting(boolean)` - Set interrupt mode
- `getInitiator()` / `setInitiator(String)` - Initiator expression
- `getFormKey()` / `setFormKey(String)` - Form key
- `getFormProperties()` / `setFormProperties(List<FormProperty>)` - Form properties

**When to Use:** As the starting point of every process.

**Design Pattern:** Specialized Event for process initiation

**Important:** Every executable process must have at least one StartEvent

---

### EndEvent

**Purpose:** Marks the completion of a process or flow.

**Responsibilities:**
- Signaling process completion
- Managing end conditions
- Handling event definitions
- Supporting termination
- Tracking end metadata
- Enabling process conclusion

**Key Properties:**
- `eventDefinitions` - End behaviors (inherited from `Event`)
- `id` - Event identifier
- `name` - Event name

**Key Methods:**
- `addEventDefinition(EventDefinition)` - Add behavior (inherited from `Event`)

> **Note:** `EndEvent` itself is an empty class (only `clone()` / `setValues()`). A terminate end event is an `EndEvent` whose `eventDefinitions` list contains a `TerminateEventDefinition`.

**When to Use:** To mark process or sub-process completion.

**Design Pattern:** Specialized Event for process termination

**Types:** None, Terminate, Error, Signal, Message, etc.

---

### SequenceFlow

**Purpose:** Defines the order of execution between flow nodes.

**Responsibilities:**
- Connecting flow elements
- Managing flow direction
- Handling flow conditions
- Supporting flow properties
- Tracking flow state
- Enabling flow navigation

**Key Properties:**
- `sourceRef` - Source element ID
- `targetRef` - Target element ID
- `conditionExpression` - Flow condition
- `skipExpression` - Expression to skip the flow
- `id` - Flow identifier (inherited)
- `name` - Flow name (inherited)

**Key Methods:**
- `getSourceRef()` - Get source element
- `getTargetRef()` - Get target element
- `getConditionExpression()` - Get condition
- `getSkipExpression()` - Get skip expression

> **Note:** `SequenceFlow` has no `isDefault` flag — the default outgoing flow is declared on the source node via `Activity.defaultFlow` / `Gateway.defaultFlow`.

**When to Use:** To connect any two flow elements.

**Design Pattern:** Link/Connection pattern

**Important:** Defines the actual execution path through the process

### BpmnModel Class

```java
public class BpmnModel {
    
    protected Map<String, List<ExtensionAttribute>> definitionsAttributes = new LinkedHashMap<>();
    protected List<Process> processes = new ArrayList<>();
    protected Map<String, GraphicInfo> locationMap = new LinkedHashMap<>();
    protected Map<String, GraphicInfo> labelLocationMap = new LinkedHashMap<>();
    protected Map<String, List<GraphicInfo>> flowLocationMap = new LinkedHashMap<>();
    protected List<Signal> signals = new ArrayList<>();
    protected Map<String, MessageFlow> messageFlowMap = new LinkedHashMap<>();
    protected Map<String, Message> messageMap = new LinkedHashMap<>();
    protected Map<String, Error> errorMap = new LinkedHashMap<>();
    protected Map<String, ItemDefinition> itemDefinitionMap = new LinkedHashMap<>();
    protected Map<String, DataStore> dataStoreMap = new LinkedHashMap<>();
    protected List<Pool> pools = new ArrayList<>();
    protected Map<String, String> namespaceMap = new LinkedHashMap<>();
    protected String targetNamespace;
    protected String sourceSystemId;
    
    public void addProcess(Process process) {
        processes.add(process);
    }
    
    // ID lookup across all processes (including nested sub-processes)
    public FlowElement getFlowElement(String id) {
        for (Process process : processes) {
            FlowElement foundFlowElement = process.getFlowElement(id);
            if (foundFlowElement != null) {
                return foundFlowElement;
            }
        }
        // ... nested sub-processes are searched as well
        return null;
    }
}
```

### Process

```java
public class Process extends BaseElement {
    
    protected String name;
    protected boolean executable = true;
    protected String documentation;
    protected IOSpecification ioSpecification;
    protected List<ActivitiListener> executionListeners = new ArrayList<>();
    protected List<Lane> lanes = new ArrayList<>();
    protected List<FlowElement> flowElementList = new ArrayList<>();
    protected List<ValuedDataObject> dataObjects = new ArrayList<>();
    protected List<Artifact> artifactList = new ArrayList<>();
    protected List<String> candidateStarterUsers = new ArrayList<>();
    protected List<String> candidateStarterGroups = new ArrayList<>();
    protected List<EventListener> eventListeners = new ArrayList<>();
    protected Map<String, FlowElement> flowElementMap = new LinkedHashMap<>();
    
    public void addFlowElement(FlowElement element) {
        flowElementList.add(element);
        element.setParentContainer(this);
        if (StringUtils.isNotEmpty(element.getId())) {
            flowElementMap.put(element.getId(), element);
        }
        if (element instanceof FlowElementsContainer) {
            flowElementMap.putAll(((FlowElementsContainer) element).getFlowElementMap());
        }
    }
    
    public Collection<FlowElement> getFlowElements() {
        return flowElementList;
    }
    
    public boolean isExecutable() {
        return executable;
    }
    
    public void setExecutable(boolean executable) {
        this.executable = executable;
    }
}
```

## Model Traversal

The `BpmnModel` does not include a built-in visitor pattern or traverser utility.
To traverse the model, iterate directly over `BpmnModel.getProcesses()` and then over `Process.getFlowElements()`.
Each `FlowElement` can be checked with `instanceof` to identify tasks, gateways, events, and sequence flows.

```java
for (Process process : model.getProcesses()) {
    for (FlowElement element : process.getFlowElements()) {
        if (element instanceof UserTask) {
            UserTask userTask = (UserTask) element;
            // Process user task
        } else if (element instanceof ServiceTask) {
            ServiceTask serviceTask = (ServiceTask) element;
            // Process service task
        } else if (element instanceof SequenceFlow) {
            SequenceFlow flow = (SequenceFlow) element;
            // Process sequence flow
        }
        // Check for nested sub-processes
        if (element instanceof SubProcess) {
            SubProcess subProcess = (SubProcess) element;
            // Recurse into sub-process flow elements
        }
    }
}
```

For lookups by ID, use `BpmnModel.getFlowElement(String id)` which returns the matching `FlowElement` across all processes (including nested sub-processes).

## Validation

BPMN model validation is provided by `org.activiti.validation.validator.impl.BpmnModelValidator`
in the `activiti-process-validation` module. It validates process definitions, checks for duplicate IDs,
verifies constraints, and returns a list of `ValidationError` objects.

Validation is invoked automatically by the engine at deployment time. It can also be called programmatically:

```java
BpmnModelValidator validator = new BpmnModelValidator();
List<ValidationError> errors = new ArrayList<>();
validator.validate(bpmnModel, errors);

if (!errors.isEmpty()) {
    for (ValidationError error : errors) {
        System.err.println(error.getDefaultDescription());
    }
}
```

The validator uses `Problems` and `Constraints` constants to identify specific validation issues.
Custom validators can be registered by extending `ProcessLevelValidator` or `ActivitiLevelValidator`.

## Serialization

### XML Serialization

The BPMN model is serialized to and from XML by `BpmnXMLConverter` in the `activiti-bpmn-converter` module:

```java
// Convert BpmnModel to XML (byte[])
BpmnXMLConverter converter = new BpmnXMLConverter();
byte[] xmlBytes = converter.convertToXML(bpmnModel);
String xmlString = new String(xmlBytes, StandardCharsets.UTF_8);

// Parse BPMN XML into BpmnModel (the stream is wrapped in an InputStreamProvider)
InputStream inputStream = ...;
BpmnModel model = converter.convertToBpmnModel(() -> inputStream, false, false);
```

### JSON Serialization

The model classes are annotated with Jackson `@JsonIgnore` where appropriate. The `BpmnModel`
and its elements can be serialized to JSON using standard Jackson `ObjectMapper`:

```java
ObjectMapper mapper = new ObjectMapper();
String json = mapper.writeValueAsString(bpmnModel);
BpmnModel parsed = mapper.readValue(json, BpmnModel.class);
```

> **Note:** The JSON serialization does not round-trip perfectly — layout and graphical information
> may be lost. Use XML conversion for persistence.

### Creating a Model Programmatically

```java
public class ModelBuilderExample {
    
    public BpmnModel createSimpleProcess() {
        BpmnModel model = new BpmnModel();
```

### Analyzing a Model

```java
public class ModelAnalyzer {
    
    public void analyze(BpmnModel model) {
        System.out.println("Process Count: " + model.getProcesses().size());
        
        for (Process process : model.getProcesses()) {
            System.out.println("\nProcess: " + process.getName());
            
            int taskCount = 0;
            int gatewayCount = 0;
            int eventCount = 0;
            
            for (FlowElement element : process.getFlowElements()) {
                if (element instanceof Task) {
                    taskCount++;
                } else if (element instanceof Gateway) {
                    gatewayCount++;
                } else if (element instanceof Event) {
                    eventCount++;
                }
            }
            
            System.out.println("  Tasks: " + taskCount);
            System.out.println("  Gateways: " + gatewayCount);
            System.out.println("  Events: " + eventCount);
        }
    }
}
```

## Best Practices

### 1. Use Meaningful IDs

```java
// GOOD
userTask.setId("approve_order");

// BAD
userTask.setId("task1");
```

### 2. Validate Early

The engine validates BPMN models automatically at deployment. For programmatic validation:

```java
BpmnModelValidator validator = new BpmnModelValidator();
List<ValidationError> errors = new ArrayList<>();
validator.validate(model, errors);
if (!errors.isEmpty()) {
    // Handle validation errors
}
```

### 3. Use getFlowElement for Lookups

`BpmnModel.getFlowElement(String id)` provides lookups across all processes and nested sub-processes.

### 4. Model Classes Are Not Thread-Safe

Reading the model is safe, but modifications should not be done concurrently.

## API Reference

### Key Classes

- `BpmnModel` - Root model container
- `Process` - BPMN process definition
- `BaseElement` - Abstract base for all elements
- `FlowElement` - Base for elements in process flow
- `FlowNode` - Base for nodes with incoming/outgoing flows
- `Activity` - Task and sub-process base
- `Gateway` - Decision points
- `Event` - Event base class
- `SequenceFlow` - Flow connections
- `BpmnModelValidator` - Validates model against BPMN and Activiti constraints (concrete class in `activiti-process-validation`)
- `BpmnXMLConverter` - Converts between `BpmnModel` and BPMN 2.0 XML (in `activiti-bpmn-converter`)
