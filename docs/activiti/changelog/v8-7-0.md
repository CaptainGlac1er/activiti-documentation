# Version 8.7.0

**Released:** 2025-02-03

A feature-focused release. The headline additions are **BPMN link events**, **JSON Patch variable mapping** in process extensions, and a configurable **cache limit** for the process definition deployment cache.

## New Features

- **BPMN link events** — support for link event source and target elements in process definitions, including BPMN model classes, XML converters, validation for missing source/target, and correct process diagram rendering.
- **JSON Patch variable mapping** — process extension variable mappings can now use JSON Patch expressions to map individual JSON properties instead of whole variables.
- **More datetime formats** — the date/time formatter provider accepts a wider set of formats.
- **Validation errors with keys and params** — validation error messages now carry machine-readable keys and parameters.
- **Deployment cache limit** — the process definition deployment cache and the process extension model cache now support a configurable LRU size limit instead of growing unbounded.
- **TaskAdminRuntime query** — new API to find the last created task for a given process instance id and task definition key.

## Bug Fixes

- Fixed a race condition in service tasks using connectors.
- Fixed invalid JSON Patch mapping when the source variable is an empty string.
- Fixed importing projects containing multi-instance loops.
- Imported processes using link events are now available in the workspace.
- Fixed a `PersistenceException` when async job shutdown ran inside a listener.

## Notable Changes

- **Performance** — improved query performance for historic tasks and runtime tasks.
- Added the `details_` column to the MariaDB schema.
- Reduced logging level of `ActivitiException` and shutdown-time `CommandContext` exceptions from ERROR to WARN.
- Upgraded to Spring Boot 3.3.x (final 3.3.4).

## Use Cases

### Navigating a process without adjacent sequence flows

Link events let execution jump to a non-adjacent part of the same process — for example, sending a case back to an earlier stage for rework, or jumping to a shared cleanup stage — without drawing long crossing sequence flows:

```xml
<intermediateThrowEvent id="reworkTrigger" name="Send back to rework">
  <linkEventDefinition id="reworkLink">
    <target>reworkCatch</target>
  </linkEventDefinition>
</intermediateThrowEvent>

<intermediateCatchEvent id="reworkStage" name="Rework">
  <linkEventDefinition id="reworkCatch">
    <source>reworkLink</source>
  </linkEventDefinition>
</intermediateCatchEvent>
```

:::caution
The `<target>` and `<source>` values reference the **id of the opposing `linkEventDefinition`**, not the id of the catch or throw event. A wrong reference deploys without error but the link fails silently at runtime.
:::

Validation now rejects link events with a missing source or target, and error messages include the event id and name to make problems easier to locate.

### Fine-grained JSON variable mapping with JSON Patch

Instead of mapping whole variables, a `JSONPATCH` mapping applies an RFC 6902 patch to an existing JSON variable, copying single properties from one variable into another:

```json
{
  "mappings": {
    "enrichTask": {
      "outputs": {
        "person": {
          "type": "JSONPATCH",
          "value": [
            { "op": "add", "path": "/lastname", "value": "${lastName}" }
          ]
        }
      }
    }
  }
}
```

Patch values support `${...}` expressions, and the mapping fails fast when the source variable is an empty string. 8.8.0 extends paths with variable interpolation and array element replacement.

### Bounding the deployment cache

Long-running engines that deploy many process definitions can cap the in-memory process definition cache to prevent unbounded growth:

```yaml
spring:
  activiti:
    process-definition-cache-limit: 100
```

### Finding the last created task for an activity

`TaskAdminRuntime` exposes a direct lookup for the most recently created task of a given activity in a process instance — handy for audit views and service automation:

```java
import org.activiti.api.task.model.Task;
import org.activiti.api.task.runtime.TaskAdminRuntime;

Task task = taskAdminRuntime.lastCreatedTaskByProcessInstanceIdAndTaskDefinitionKey(
    processInstanceId, "approveOrder");
```
