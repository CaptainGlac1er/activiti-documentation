# Version 8.8.0

**Released:** 2026-02-25

The largest release in this range. The headline features are **ephemeral variables** (process variables that are not persisted to the event store) and **root process instance identifiers** exposed on process instances and tasks.

## New Features

- **Ephemeral variables** — a new `ephemeral` property on variable definitions in the process extension JSON. Ephemeral variables participate in execution but are not written to the event store: the event producer sends an empty value for them, update events null out the previous value, and the query service API exposes the `ephemeral` flag so clients can filter them out. Task variables are exempt from the ephemeral check, and the property also applies to connector variables.
- **Root process instance id** — `ProcessInstance` now carries the id of the root process instance in a call-activity hierarchy (also added to tasks), and the V2 process instance model includes the linked process instance id. Useful for correlating child instances back to the initiating process.
- **Batch process definition lookup** — `GetProcessDefinitionsPayload` supports multiple process definition IDs in a single call, and a new API retrieves the latest versions of process definitions.
- **Process definition query extension** — the process definition query can now include non-user-startable processes (previously only user-startable ones were returned by default).
- **JSON Patch variable mapping extensions** — the JSON Patch mapping introduced in 8.7.0 now supports arrays (including inner empty arrays), variables inside the patch path field, and replacing array elements.

## Bug Fixes

- Initiator is now passed into call activity subprocesses (it was previously dropped).
- Task name and description are truncated to enforce database length limits instead of failing.
- Pagination is no longer ignored in the process definition search endpoint.
- Parallel multi-instance tasks: the collection and loopCardinality expressions are evaluated only at task creation, not again when a task is closed.
- Task names set by task listeners now show up in the interfaces.
- Corrected the `total` count when querying historic process instances.
- Eliminated duplicated events in certain execution paths.
- Catch-all error boundary events are now processed only after specific error boundaries are exhausted.

## Notable Changes

- **Subprocess termination** — support added for terminating subprocesses from the API.
- **Start event subscriptions of previous deployments are disabled** — superseded process definition versions no longer react to start events, preventing accidental triggering of old versions.
- **Auto-deployment disabled** by default behavior change in deployment handling.
- Removed the `ACT_IDX_IDENT_LNK_TASK` index from the schema.
- Tasks are updated on every `TaskListener` callback that changes them, keeping query results consistent.
- `ProcessCompletedEvent` now includes actor information.
- Activity-started events are now emitted for async multi-instance tasks.
- Upgraded to Spring Boot 3.5.x (final 3.5.7) and updated the Jakarta dependencies.
