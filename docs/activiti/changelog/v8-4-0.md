# Version 8.4.0

**Released:** 2024-04-09

## New Features

- **Java 8 date support in date formatting** — `DateFormatterProvider` now supports Java 8 date/time types (AAE-21057).

## Bug Fixes

- **Variable type handling** — variable type should always resolve to `BigDecimal` where expected (AAE-27057).
- **MAP_ALL variables mapping** — fixed variable mapping for `MAP_ALL` (AAE-20402).

## Notable Changes

- Removed the disabled CSRF configuration (AAE-19764).
- Upgraded to Spring Boot 3.2.4 (AAE-21381).
- Upgraded the PostgreSQL driver (AAE-21068).

## Use Cases

### Java 8 date/time variables

The `DateFormatterProvider` now understands Java 8 date/time values, so date variables can be set as `LocalDate`, `LocalDateTime`, or `ZonedDateTime` and are converted to `Date` using the configured zone (UTC by default) — no string formatting required:

```java
import java.time.LocalDateTime;
import java.util.Map;
import org.activiti.api.process.model.payloads.SetProcessVariablesPayload;
import org.activiti.api.process.runtime.ProcessRuntime;

processRuntime.setVariables(new SetProcessVariablesPayload(
    processInstanceId,
    Map.of("dueDate", LocalDateTime.of(2026, 8, 29, 12, 0))
));
```

### Mapping all variables of an element

`MAP_ALL` / `MAP_ALL_INPUTS` / `MAP_ALL_OUTPUTS` map every applicable variable between the process and an element without listing them individually — the 8.4.0 fix ensures these mappings apply correctly:

```json
{
  "mappings": {
    "paymentTask": {
      "mappingType": "MAP_ALL_INPUTS"
    }
  }
}
```
