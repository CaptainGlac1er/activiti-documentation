# Version 9.0.0

**Released:** 2026-03-05

A major release that moves the engine to Java 25 and restructures how expressions are resolved internally.

## New Features

- **Upgraded to Java 25** — the platform now builds and runs on Java 25, aligning the engine with the current LTS line.
- **Expression evaluation behind an SPI** — the internal `ExpressionManager` now delegates to a pluggable `ExpressionFactory` service-provider interface, so expression resolution can be replaced or extended without modifying engine internals.

## Notable Changes

- Removed an obsolete Testcontainers workaround that is no longer required.

## Breaking Changes & Mitigations

- **Requires Java 25** — the platform builds and runs on Java 25 (8.8.0 targets Java 21). **Mitigation:** upgrade the JDK of your build and runtime, or stay on 8.8.0 until your infrastructure is ready.
- **Expression evaluation via SPI** — the engine's `ExpressionManager` now obtains the EL factory through the `jakarta.el.ExpressionFactory` service-provider interface instead of instantiating it directly. Default behavior (the built-in JUEL implementation) is unchanged. **Mitigation:** none for standard usage; the SPI additionally allows supplying a custom EL implementation via `META-INF/services`.

## Use Cases

- **Java 25 applications** — if your stack has already moved to Java 25, this release lets you align Activiti with your runtime instead of maintaining an older JDK baseline.
- **Custom expression handling** — expression evaluation now resolves through the `jakarta.el.ExpressionFactory` service-provider interface. An application that needs a custom EL implementation can provide one by registering a `META-INF/services/jakarta.el.ExpressionFactory` entry on the classpath, without modifying engine code.
